# 摩尔勇士宠物洗点 GUI

基于 `ref/moer.py` 中 `xd` 洗宠流程实现的桌面界面。界面会读取背包宠物、仓库宠物和五类洗点道具，支持基础五项或战斗面板两种目标判断，并逐次展示洗点结果。仓库初始列表只读取昵称、种类和等级，选中具体宠物时才通过 `_get_pet_info` 获取详细资料。

背包列表提供“放回仓库”按钮，仓库列表提供“取回背包”按钮，分别调用 `_pet_back_store` 和 `_pet_back_bag`。仓库宠物需要取回背包后才能洗点。

“成长预测”页会结合所选宠物的当前等级、转生次数、已分配点总数、五项努力值和战斗面板，按本地 V14 数据库的候选范围和手动自由加点进行匹配。只有当前五项努力值与五项战斗值全部完全一致的候选才会用于推算 0转1级、0转99级和10转99级；若存在多解，界面按网页权重排序并列出全部候选的基数、当前加点和三档完整面板，不再使用近似拟合兜底。

“基数与洗宠模拟”页会按当前服务器和宠物种类读取 `ref/pet_bases.json` 中的原始基数。手动输入五项洗宠波动后得到目标基数，并可分别配置 0转99级、0转任意级别和10转99级的自由加点，最终同时计算四种场景的五项及完整战斗面板。

运行时预测数据已从网页中独立提取，只读取 `ref/pet_bases.json` 和 `ref/egg_codes.bin`。战斗面板统一使用 V14 公式计算，不依赖网页或实测面板库。网页数据更新后，可运行 `python tools/extract_prediction_data.py` 重新生成这两个资源文件。

## 运行

需要 Python 3.10+。项目使用 Python 标准库 Tkinter，协议参考文件还依赖 `uncompyle6`。

```powershell
python app.py
```

输入米米号、明文密码和服务器后连接。密码只保存在当前进程内，不会写入文件。

## 目标判断

- 绿色成长、红色成长：成长不低于期望值。
- 大丸子：成长加五项；体力、力量、敏捷按不低于判断，耐力、智力按不高于判断。
- 紫色五项、红色五项：不包含成长目标。
- 战斗面板方式：生命、攻击、速度按不低于判断，防御、魔力按不高于判断。
- 期望值填 `0` 表示忽略该项。

每次任务都有最多洗点次数，道具不足或点击停止时会安全结束循环。
