# 摩尔勇士宠物洗点 GUI

基于 `ref/moer.py` 中 `xd` 洗宠流程实现的桌面界面。界面会读取背包宠物、仓库宠物和五类洗点道具，支持基础五项或战斗面板两种目标判断，并逐次展示洗点结果。仓库初始列表只读取昵称、种类和等级，选中具体宠物时才通过 `_get_pet_info` 获取详细资料。

宠物详情区提供“修改昵称”按钮，可修改背包或仓库宠物昵称，并通过 `_pet_change_name` 调用 1552 协议。背包列表还提供“放回仓库”按钮，仓库列表提供“取回背包”和“放生宠物”按钮，分别调用 `_pet_back_store`、`_pet_back_bag` 和 1561 协议。放生前会弹窗二次确认，确认后无法恢复；仓库宠物需要取回背包后才能洗点。

“成长预测”页会结合所选宠物的当前等级、转生次数、已分配点总数、五项努力值和战斗面板，按本地 V14 数据库的候选范围和手动自由加点进行匹配。程序优先返回五项努力值与五项战斗值全部完全一致的候选；仅在没有精确候选时，才采用网页同款显示容差（生命、攻击、防御、速度允许相差 5，魔力允许相差 1），并在界面明确标注为容差结果。符合条件的候选会用于推算 0转1级、0转99级和10转99级；若存在多解，界面按网页权重排序并列出全部候选的基数、相对基础基数浮动、当前加点和三档完整面板。忘记自由加点分配时，可点击“未知加点预测”：工具会临时重置宠物自由点，以重置回包计算预测，再按重置前后的五项努力值差恢复原加点；恢复完成前会阻止关闭窗口。

“基数与洗宠模拟”页会按当前服务器和宠物种类读取 `ref/pet_bases.json` 中的原始基数。手动输入五项洗宠波动后得到目标基数，并可分别配置 0转99级、0转任意级别和10转99级的自由加点，最终同时计算四种场景的五项及完整战斗面板。

“杂项”页会分别显示背包和仓库中的巨石碎片、经验书数量。可按输入数量将巨石碎片兑换为大丸子，或批量使用经验书；“一键升级10转99级”会按每本99999经验计算经验树缺口，自动使用所需经验书后为当前宠物分配经验并转生。还可读取经验树剩余经验，向当前背包宠物分配指定经验（不转生）、升级到0转99级，或一键分配经验树的全部剩余经验并在达标后自动转生。宠物达到10转99级后的多余经验会保留在经验树中。分配经验后会通过1603协议自动分配属性点，并刷新宠物和经验树数据。开蛋下拉框包含 `ref/item_names.py` 中的全部精灵蛋和精品蛋，开启时优先使用背包库存，不足部分从仓库取出，再通过1130协议批量开启。地图传送下拉框内置从客户端地图配置提取的地图名称、编号和可用落点，通过1004协议传送。

运行时预测数据已从网页中独立提取，只读取 `ref/pet_bases.json` 和 `ref/egg_codes.bin`。宠物技能名称读取自 ClientCoreDLL 中提取的 `ref/skills.xml`。战斗面板统一使用 V14 公式计算，不依赖网页或实测面板库。网页数据更新后，可运行 `python tools/extract_prediction_data.py` 重新生成预测资源文件。

## 运行

需要 Python 3.10+。项目使用 Python 标准库 Tkinter，协议参考文件还依赖 `uncompyle6`。

```powershell
python app.py
```

输入米米号、明文密码和服务器后连接。密码只保存在当前进程内，不会写入文件。

## 目标判断

- 只有 0 转宠物可以洗点；转生次数不为 0 时，“开始洗点”不可用，后端也会拒绝请求。
- 绿色成长、红色成长：成长不低于期望值。
- 大丸子：成长加五项；体力、力量、敏捷按不低于判断，耐力、智力按不高于判断。
- 紫色五项、红色五项：不包含成长目标。
- 战斗面板方式：生命、攻击、速度按不低于判断，防御、魔力按不高于判断。
- 期望值填 `0` 表示忽略该项。
- 三组候选均可通过勾选启用，至少需选择一组；每组内的非零条件需同时满足，任一启用的候选组满足时即停止洗点。
- “一键填充”会按当前宠物等级与转生次数，以全力加点分别填入体力+力量、力量+敏捷、体力+敏捷（或对应的战斗面板），三组成长均使用默认满成长，其余项置 `0`。

每次任务都有最多洗点次数，道具不足或点击停止时会安全结束循环。
每次洗点成功并读取到最新宠物数据后，程序会同步写入应用目录下的 `pet_results.db`，记录账号、服务器、道具类型和本次洗点结果。
